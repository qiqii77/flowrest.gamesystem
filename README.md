# BlueCourt

以現有 HTML / CSS / JavaScript 介面延伸的賽事管理本機原型。

## 本機預覽

在專案目錄執行：

```powershell
python -m http.server 8000 --bind 127.0.0.1
```

開啟 http://127.0.0.1:8000 。建議使用 localhost HTTP，讓密碼衍生所需的 Web Crypto 可正常運作。
所有本機資料都屬於該網址的瀏覽器儲存空間。

## 帳號與權限

觀眾免登入，可查看首頁賽事、公開賽程與即時比分。登入畫面僅顯示電子郵件與密碼，不顯示身分選項。
介面依帳號已獲得的最高權限決定，無法在登入時自行選擇取得管理權限。

| 介面 | 功能 |
| --- | --- |
| 系統管理員 | 所有賽事管理、賽事登錄、賽事管理員指派、使用者系統權限管理、操作紀錄 |
| 賽事管理員 | 僅限指派賽事的總覽、報名審核、賽事更動、場次裁判指派與比分修正 |
| 裁判 | 僅限指派場次的報到、狀態更新、上下箭頭記分、歸零、最終比分確認與鎖定 |
| 選手 | 個人中心、已報名賽事、個人賽程、聯絡資料編輯 |

新註冊帳號一律為選手。系統管理員透過「使用者管理 → 賽事管理員與裁判指派」指定賽事管理員。
賽事管理員透過「人員管理」將已註冊帳號指派給某場次；該帳號重新登入或資料同步後便會取得裁判介面。
解除所有場次指派後恢復選手介面（若另有更高權限，則顯示更高權限介面）。

登入視窗展開「本機功能體驗帳號」查看帳號，直接填入電子郵件與密碼即可體驗；所有體驗帳號密碼為 `BlueCourt2026!`：

| 帳號 | 介面／範圍 |
| --- | --- |
| admin@bluecourt.tw | 系統管理員，全部賽事 |
| volleyball-manager@bluecourt.tw | 賽事管理員，僅大學排球聯賽（21 天內開始、報名中） |
| staff@bluecourt.tw | 賽事管理員，僅台灣羽球盃 |
| referee@bluecourt.tw | 裁判，台灣羽球盃的示範場次 |
| player@bluecourt.tw | 選手，已有一筆示範報名 |
| other@bluecourt.tw | 另一個已註冊選手，可供指派操作 |

## 操作流程

1. 首頁選擇開放報名的賽事。已登入時直接進入報名頁；未登入時先顯示登入視窗，可轉至註冊。登入或註冊成功後會直接返回原選定賽事的報名頁，重新整理也保留原選擇。
2. 在同一個報名頁填寫項目、隊伍名稱、姓名、電話、生日及緊急聯絡人後送出；既有資料會預填，送出時同步更新個人聯絡資料。
3. 報名會立即出現在選手的報名列表，管理員可在賽事範圍內核准或不通過。
4. 管理員關閉報名時，系統按組別、已核准隊伍順序，自動產生首輪配對。奇數隊伍安排輪空；尚未核准的報名不排入賽程。
5. 到報名截止日結束（台灣時間）後，頁面載入、切回前景或每 30 秒檢查時也會自動關閉並排程。頁面未執行期間沒有背景排程服務。
6. 賽事管理員指派場次裁判。裁判完成雙方報到後，將賽況設為「開始」，即可計分；延後及取消狀態停用記分板。
7. 裁判點「結束並送出比分」，再次確認後鎖定結果，不能改分、歸零或更改報到與狀態。
8. 裁判可送出比分修正請求。管理員在「人員管理」查看，於「賽事更動」填寫原因後重新開放；原裁判重新開始場次並修正，最後再次送出。
9. 賽事更動可修改日期、時間、場地及狀態，並選擇將同日、原場地後續尚未開始的場次一起延後。已開始、取消或鎖定的後續場次不受批次延後影響。

一般新賽事的自動排程目前是首輪依序配對；不包含通用循環賽、種子排序或運動專用自動判勝。
記分板分開記錄「局數（大比分）」與「本局得分（小比分）」，兩者均可使用箭頭調整。
「記錄本局並開始下一局」保留該局紀錄、勝方局數加一、本局得分歸零；可選擇只歸零本局或歸零全部比分。最終送出會同時鎖定局數與得分。

## 示範賽事與場地

系統管理員可瀏覽台灣羽球盃、大學排球聯賽、網球積分賽三場示範賽事。
台灣羽球盃包含男子單打、女子單打、混合雙打，每項 16 組，共 48 組及 45 場淘汰賽：
每項包含 8 場16強、4 場8強、2 場準決賽及1場決賽，並可依項目篩選。
前輪確認最終比分時，勝方自動帶入下輪；下輪已開始或已有比分時，禁止直接重開前輪，避免覆蓋已進行的比賽。
示範參賽者紀錄未啟用登入；人員指派使用上述可登入帳號或自行註冊的帳號。
示範資料會補入既有本機資料，保留已存在的帳號與修改紀錄，不需要清除瀏覽器儲存空間。

場館與場地分開儲存，場地名稱可為文字，例如「主場館／中央球場」「副場館／東側球場」。
賽事登錄可用每行「場館｜場地名稱」設定完整清單；未填清單時才使用場地數產生預設名稱。
批次延後只影響同日、同場館與同場地的後續場次。

## 資料與同步範圍

- `demo-data.js`：示範資料補齊、舊版資料欄位相容與完整淘汰賽。
- `competition.js`：資料、帳號驗證、賽事範圍檢查與操作規則。
- `workspace-views.js`：角色工作區、表單及記分板畫面。
- `script.js`：導覽、事件處理、公開賽況與同步。
- `bluecourt-v2` 儲存使用者、賽事、報名、場次與操作紀錄；`bluecourt-session-v2` 儲存目前帳號。
- 相同瀏覽器、相同網址的分頁會同步資料與登入帳號。不同裝置／瀏覽器無法互通。
- 同步時會保留焦點所在、尚未送出的表單；已更新場次的舊表單會被拒絕覆蓋，最終比分確認也會檢查版本。
- 密碼以每帳號獨立 salt 的 PBKDF2-SHA256 衍生值儲存，不儲存明文密碼。
- 舊版 `bluecourt-managed-events` 賽事定義會在首次初始化時帶入；原始舊資料不刪除。舊版登入未保存密碼，不能視為新帳號身分憑證，請重新註冊。
- 目前是可操作的前端原型。瀏覽器本機資料與前端權限可被使用者修改，不能作為正式授權或多裝置即時比賽系統。正式部署需要伺服器驗證、資料庫與即時通訊，並移除體驗帳號。

## 驗證

需要 Node.js 22 或更新版本：

```powershell
node --test tests/competition.test.cjs
node tests/browser.cjs
```

第一項測試帳號權限、跨賽事隔離、指派、報名、自動排程、記分鎖定與修正。
第二項使用 Windows 上的 Chrome 或 Edge 無頭模式與獨立暫存資料，
實際走過註冊報名、四種角色、比分確認、管理員修正、雙分頁同步與 390px 手機版檢查。
不需安裝 npm 套件；瀏覽器測試會啟動及結束自己的暫時本機伺服器。
測試截圖與瀏覽器測試資料留在系統暫存目錄 `bluecourt-check-*`，不使用日常瀏覽器設定。

## 首頁與當日賽況

首頁依序為今日即時賽況、賽事資訊、賽程；已移除首頁報名宣傳卡、熱門選手與平台簡介。
立即報名按鈕僅出現在報名中的賽事條目，點選後沿用登入／註冊完成直接回報名頁的流程。
首頁 Live 及「當日賽況」僅顯示台灣時間當日的場次；「完整賽程」仍可查看其他日期。

三場示範賽事日期以開啟當天為基準：台灣羽球盃當日進行中、大學排球聯賽在21天後開始且報名中、網球積分賽在60天後開始且報名中。
隔日重新開啟頁面時，示範日期會向前平移；既有比分與操作紀錄保留。
新增排球聯賽管理員 volleyball-manager@bluecourt.tw，密碼為 BlueCourt2026!，僅能管理大學排球聯賽。
新增帳號與指派只在首次補齊資料時執行；之後由系統管理員解除的指派不會自動補回。

## 外部直播預覽框

首頁最上方顯示當日進行中賽事的直播預覽框，框內左上角有紅點與 LIVE 標示。
同一賽事的多場比賽共用一個直播入口；點擊整個框會在新分頁開啟該賽事的外部直播網址。
羽球示範賽目前使用 YouTube 首頁，不代表已串接賽事影片；畫面標示「示範直播入口」。
系統管理員或負責該賽事的管理員可在「賽事總覽 → 直播連結設定」修改網址。
賽事登錄也能直接填寫直播網址；僅接受 http/https 網址，留空時預覽框會顯示尚未設定且不提供跳轉。

## 個人中心與快速登入入口

帳號選單的「個人中心」會依帳號權限返回登入後的工作區。
登入介面保留 LINE、Google、Facebook 快速登入入口與電子郵件登入。
LINE／Google／Facebook 入口目前清楚標示「即將開放」，點擊會提示改用電子郵件，不會建立登入狀態或取消原選定的報名賽事。
正式第三方帳號連動仍需配置服務端驗證與各平台授權設定；目前未串接第三方登入。

## 表單管理

系統管理員與賽事管理員的個人中心橫向選單新增「表單管理」。
系統管理員可選擇任一賽事，賽事管理員僅能設定自己負責的賽事，選手與裁判無此編輯權限。

- 比賽項目：新增或調整可報名項目；已有報名或賽程的項目禁止直接刪除、改名。
- 基本欄位：可修改名稱、顯示與必填狀態；姓名、選手／隊伍名稱維持固定必填。
- 自訂欄位：可新增或移除單行文字、多行文字、數字、下拉選單、勾選確認、日期、電子郵件與電話，最多總計40欄。
- 表單預覽：可檢視尚未儲存的報名頁；儲存後套用至實際報名頁。
- 繳費預留：可設定免費或預留繳費，包含新臺幣費用、銀行轉帳／信用卡／LINE Pay／現場繳費及補充說明。
- 收款尚未串接：不提供付款頁、不收集卡號、不進行扣款或確認入帳。報名者僅可留下預計方式，資料狀態為尚未開放付款。
- 已送出的報名會保存欄位名稱、答案、表單版本與費用快照，後續變更表單不影響舊資料，可在「報名審核」及選手「報名與隊伍」查看。
- 表單與報名送出會檢查版本，防止舊設定覆蓋新版本；相同帳號其他分頁的更新會保留正在編輯的欄位與繳費設定。

模組：registration-forms.js 負責表單規則與驗證；registration-form-views.js 負責動態報名欄位；form-editor.js 負責雙欄編輯、條件設定及互動預覽。
參考：[ACCUPASS 報名表設定](https://accupass.uservoice.com/knowledgebase/articles/129763)。

## 題目顯示條件、外部系統與審核視窗

首頁選單已移除重複的「賽事管理／隊伍面板／計分中心」，以「報名中的比賽／即將開始的比賽／今日賽況」快捷入口替代；登入後從帳號選單的個人中心返回工作區。

表單管理採左側題目清單、右側設定面板，分為「內容／作答設定／顯示條件」。
可新增、複製、上下移動自訂題目，清單標示題型、必填與有顯示條件。
移動題目後如破壞條件依賴順序，儲存時會提示重新調整。

- 顯示條件可依比賽項目、前面題目的答案或指定時間判斷，支援全部符合 AND、任一符合 OR，以及符合時顯示／隱藏。
- 答案條件提供等於、不等於、包含、已填寫、未填寫與數字比較；勾選題等於的比較內容使用 true／false。時間條件依台灣時間處理。
- 每題最多8個條件。只參照前方題目以避免循環；姓名與選手／隊伍名稱維持固定必填。
- 互動預覽可試填並確認顯示條件。實際報名時，隱藏題目會停用且不驗證必填，也不會保存其答案；後續題目不能依隱藏題目的舊答案而顯示。
- 外部系統預留名稱、用途（繳費／報名／其他）、http/https 網址與說明。啟用後在報名頁及該筆報名的明細視窗顯示另開分頁連結。
- 不自動傳送個人資料，不建立付款交易，也不同步外部付款／報名結果。若需 API 串接或金流回報，仍需後端整合。

報名審核列表只顯示隊伍、項目、申請人與狀態摘要。點擊卡片會開啟可捲動的完整資料視窗，包含已送出的題目答案、表單版本、繳費預留與外部連結；可在視窗內核准或不通過。
舊版／示範報名會顯示已有聯絡資料。明細讀取受賽事管理範圍限制，不回傳密碼雜湊或 salt。
